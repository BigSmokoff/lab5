# Архитектура плагинов nanoCAD (NRX)

Разработка под nanoCAD на C++ (NRX - nanoCAD Runtime eXtension) требует понимания многоуровневой архитектуры САПР, которая сильно перекликается с классическими концепциями AutoCAD (ARX).

**Основные аспекты NRX:**
1. **Кастомные примитивы (Custom Entities):** Наследование от `NcDbEntity` (или `AcDbEntity` в терминах совместимости). Позволяет создавать объекты со своим поведением при отрисовке (`subViewportDraw`, `subWorldDraw`), привязках (`subGetOsnapPoints`) и трансформациях. Примером служит мой плагин `AcDbTangentCircles`.
2. **Управление транзакциями:** Любое изменение базы данных чертежа должно быть обернуто в транзакцию. Это предотвращает порчу данных при сбоях и обеспечивает работу механизма Undo/Redo. Открытие объекта на чтение `kForRead` и на запись `kForWrite`.
3. **Реакторы (Reactors):** Механизм подписки на события базы данных. Схоже с [[Паттерн Наблюдатель (Observer) и сигналы Qt]], но на уровне ядра базы чертежа. Позволяет отслеживать удаление, модификацию или добавление объектов.
4. **COM и C++/CLI обертки:** Для того чтобы нативные C++ классы (NRX) были доступны из .NET API, пишутся управляемые обертки. Это требует глубокого понимания маршалинга данных между неуправляемой (unmanaged) и управляемой (managed) памятью.
