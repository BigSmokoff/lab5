# Интеграция нативного C++ и .NET через C++/CLI

При разработке под САПР (например, nanoCAD) часто возникает задача: математическое ядро и ресурсоемкие алгоритмы написаны на быстром, нерегулярном C++17/20, а интерфейс или бизнес-логика верхнего уровня — на C# (WPF, .NET API).

**Технология C++/CLI (Common Language Infrastructure):**
Позволяет в одном проекте смешивать нативный (unmanaged) и управляемый (managed) код. 
Создается класс-обертка `ref class`, который содержит внутри сырой указатель на нативный C++ объект. 

**Важные нюансы маршалинга:**
- Конвертация `std::string` <-> `System::String^`.
- Предотвращение сборок мусора (.NET Garbage Collector) от перемещения объектов в памяти, пока нативный код работает с ними (через `pin_ptr`).
- Тщательная реализация паттерна `IDisposable` (`~ClassName()` и `!ClassName()`), чтобы при уничтожении .NET-обертки корректно вызывался `delete` для внутреннего C++ указателя, иначе — гарантированная утечка памяти.
